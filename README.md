# 🧠 AI Document Question Answering System

A fully deployed Retrieval-Augmented Generation (RAG) system that lets users upload documents (PDF/TXT) and ask natural-language questions about their content — answers are generated by an LLM and grounded strictly in the uploaded document, with explicit anti-hallucination prompting.

Built from scratch to understand every layer of a real-world Generative AI application: document ingestion, chunking, embeddings, vector search, LLM-based answer generation, and cloud deployment.

**🔗 Live App:** https://ai-document-app-system-w8gr3gwwlmfzltcgav9rkm.streamlit.app
**🔗 API Docs:** https://ai-document-qa-system-5fd2.onrender.com/docs

*(Note: hosted on free tiers — the backend may take 30-50s to "wake up" after inactivity.)*

---

## ✨ Features

- 📄 Upload PDF or TXT documents
- ✂️ Automatic chunking with configurable size/overlap
- 🧬 Cloud embeddings via Google's embedding API
- 🔍 Semantic vector search using Qdrant Cloud
- 🤖 Grounded answer generation via Groq (Llama 3.1), with explicit anti-hallucination prompting
- 💬 Chat-style interface with conversation history
- ⚡ Fully deployed on free-tier cloud infrastructure

## 🏗️ Architecture

```
┌─────────────┐      ┌──────────────┐      ┌─────────────┐
│  Streamlit   │─────▶│   FastAPI    │─────▶│    Qdrant   │
│  (frontend)  │◀─────│  (backend)   │◀─────│ (vector DB) │
│ Streamlit    │      │   Render     │      │    Cloud    │
│    Cloud     │      └──────┬───────┘      └─────────────┘
└─────────────┘              │
                     ┌────────┴────────┐
                     ▼                 ▼
              ┌─────────────┐   ┌─────────────┐
              │    Groq     │   │   Google    │
              │  (LLM)      │   │ (Embeddings)│
              └─────────────┘   └─────────────┘
```

**Ingestion flow:** Document → LangChain loader → text chunks (RecursiveCharacterTextSplitter) → embeddings (Google embedding API) → stored in Qdrant Cloud

**Query flow:** Question → embedded → semantic search in Qdrant → top-k relevant chunks retrieved → stuffed into a grounding prompt → LLM (Groq/Llama 3.1) generates the answer

**Why this stack:** every heavy/local component (Ollama, ChromaDB+onnxruntime, sentence-transformers+PyTorch) was deliberately swapped for a lightweight cloud API equivalent, so the backend runs comfortably within a free-tier 512MB server — a real constraint this project was built to work within, not around.

## 🚀 Setup & Running Locally

### Prerequisites
- Python 3.10+
- Free API keys: [Groq](https://console.groq.com), [Google AI Studio](https://aistudio.google.com/apikey), [Qdrant Cloud](https://cloud.qdrant.io)

### 1. Clone the repo
```bash
git clone https://github.com/abhisaiseran123/ai-document-qa-system.git
cd ai-document-qa-system
```

### 2. Set up the Python environment
```bash
python -m venv venv
venv\Scripts\activate        # Windows
source venv/bin/activate     # macOS/Linux

pip install -r requirements.txt
```

### 3. Configure environment variables
Create a `.env` file in the project root:
```
GROQ_API_KEY=your_groq_key
GOOGLE_API_KEY=your_google_key
QDRANT_URL=your_qdrant_cluster_url
QDRANT_API_KEY=your_qdrant_key
```

### 4. Run the backend (Terminal 1)
```bash
uvicorn app.main:app --reload
```
Backend runs at `http://127.0.0.1:8000` — interactive API docs at `http://127.0.0.1:8000/docs`

### 5. Run the frontend (Terminal 2)
```bash
streamlit run streamlit_app.py
```
Opens automatically at `http://localhost:8501`

## 🎯 What This Project Demonstrates

- End-to-end RAG pipeline design (not just calling an API)
- Prompt engineering for hallucination prevention
- Clean API design with proper validation and error handling
- Separation of concerns (routers / services / schemas)
- Real cloud deployment, including diagnosing and fixing memory constraints on a resource-limited free tier
- Iteratively swapping infrastructure components (local LLM → cloud LLM, local embeddings → cloud embeddings, local vector DB → cloud vector DB) without changing the application's core logic
